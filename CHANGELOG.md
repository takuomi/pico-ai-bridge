# Changelog

## 0.1.0 - 2026-09-30 - Initial release

Zero-dependency MCP stdio bridge with six tools for server information, merged model listing, Responses, chat completions, Ollama chat, and sequential comparison. Raw mode returns the HTTP status and parsed Pico body with the configured API key redacted in values and keys. Model listing merges untagged names as `:latest`, reports `id`, `name`, `display_name`, `tag_model`, `status`, `created`, `owned_by` and tag metadata, can inspect each merged model once with `/api/show`, and reports listing errors as `{path, error: {source, status, body}}`. Default generation extracts the answer, chat and Responses refusals, reasoning, normalized tool or function calls, response ID, model, status or finish reason, timestamps, and usage or durations; malformed successful bodies return `unexpected_response`. Every Pico response field used for extraction or computation is checked for its expected JSON type when present and non-null, including comparison rows; raw bodies pass through after redaction, with non-finite or unsafe integer parsed numbers returned as source text; default 2xx bodies with these numbers return `response_parse_failed`, and Pico HTTP errors keep source text. Responses `summary_text` and `reasoning_text` parts require string `text`. Chat and Responses custom calls are validated and extracted. Chat and Ollama messages and Responses input items pass through unchanged; images attach to the last user message or form an image-only message. Chat and Ollama accept `system` alone without adding a user message; Ollama image data URIs are URL-parsed, stripped of fragments, percent-decoded and, for `;base64` media types, forgiving-base64 decoded, then sent as standard base64; malformed ones return `invalid_arguments`. Structured-output fields are passed to Pico and POST tools send `stream: false`. Ollama comparison rows include count usage with nulls for absent counts. Comparison accepts `prompt`, `messages`, or images alone, maps reasoning, `think` and `options` per API (Ollama `think` is a boolean; level strings and null go through `extra.think`), and records a result or an error per row. Integer arguments and the concurrency setting must be safe integers, and a non-finite number or unsafe integer anywhere in the arguments is rejected before any request. Tool-call argument JSON with unsafe integers stays as text. Pico HTTP errors keep their status and body. Requests use Node's `http`/`https` modules and are never aborted once sent: a caller timeout returns an error while the request keeps its FIFO permit until Pico finishes, queued requests time out without being sent, cancellation removes queued requests only, and comparison waits for a timed-out request to finish before the next model. Ollama durations and tag sizes are checked as finite numbers in default mode. Modern discovery and unsupported-version errors list only 2026-07-28, while legacy `initialize` still negotiates four revisions, with stdio batches on 2025-03-26 and 2024-11-05. Live comparison checks error isolation and timeout sequencing. The stdio adapter supports legacy `initialize` and 2026-07-28 per-request metadata, uses request metadata without connection era pinning, and accepts string or safe-integer request IDs. Includes Claude plugin and MCPB packaging with Linux, macOS, and Windows archive-level verification, unit, conformance, and live tests. `scripts/smoke-artifacts.py` extracts each archive, substitutes the manifest's declared command, arguments, and environment values, then runs `initialize` and `pico_server_info` against a local mock Pico; it does not install either archive in Claude Desktop or Claude Code.

The Claude Desktop MCPB requires `base_url` at install and has no default. The Claude Code plugin defaults to `http://localhost:11434`. Node.js 20 or newer is required for manual or Claude Code use.
